Go from a fresh install to a running workspace: add a provider, start a workspace, open it in your editor. First, [install Devsy](./install.mdx).

Run `devsy ide list` to see every supported editor. VS Code Browser (`openvscode`) and `none` (SSH only) need nothing installed locally. For any other editor, install it first. JetBrains IDEs also need [JetBrains Gateway](https://www.jetbrains.com/remote-development/gateway/).

## Devsy CLI

### 1. Add a provider

A provider decides where workspaces run. Add local Docker:

```
devsy provider add docker
```

For other backends, see [Add a Devsy Provider](../managing-providers/manage-providers.mdx).

### 2. Start a workspace

Point Devsy at a repository and choose an editor with `--ide`:

```
devsy workspace up github.com/microsoft/vscode-remote-try-node --ide vscode
```

Devsy builds the dev container and opens the editor connected to it. With `--ide none`, connect over SSH:

```
ssh WORKSPACE_NAME.devsy
```

### 2. Start a workspace

Go to **Workspaces** > **+ Create** and follow the wizard: provider, source (a repository URL or a template), editor, review, launch. When the workspace is ready, the editor opens connected to it.

<Callout title="JetBrains Gateway">
For a JetBrains IDE, Gateway opens with a prefilled form. Select **Check Connection and Continue** to start the IDE inside the workspace.
</Callout>

If you chose **None**, connect over SSH as shown above.

<Callout title="Environment variables">
To use environment variables in `devcontainer.json`, see [Environment variables in devcontainer.json](../developing-in-workspaces/devcontainer-json.mdx#environment-variables-in-devcontainerjson).
</Callout>
