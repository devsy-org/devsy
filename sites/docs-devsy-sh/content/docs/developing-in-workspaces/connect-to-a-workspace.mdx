Once a workspace is created, it is reachable over SSH at `WORKSPACE_NAME.devsy`. If you chose an IDE, Devsy opens it after the workspace starts.

Pick the IDE with `--ide` when you start a workspace, or set a default for all workspaces:

```sh
devsy workspace up my-workspace --ide vscode
devsy ide use vscode
```

Run `devsy ide list` to see every supported IDE.

### VS Code in the browser

Devsy installs [openvscode-server](https://github.com/gitpod-io/openvscode-server) in the workspace and tunnels to it from localhost.

```sh
devsy workspace up my-workspace --ide openvscode
```

### VS Code

Install the [Remote - SSH extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-ssh) and the [code CLI](https://code.visualstudio.com/docs/editor/command-line), then:

```sh
devsy workspace up my-workspace --ide vscode
```

If that fails, connect VS Code to `WORKSPACE_NAME.devsy` over SSH.

For a slow SSH connection, set the Remote - SSH connection timeout in seconds:

```sh
devsy workspace up my-workspace --ide vscode --ide-option SSH_CONNECT_TIMEOUT=60
```

Alternatively, set the option for all VS Code workspaces with `devsy ide set vscode -o SSH_CONNECT_TIMEOUT=60`. The value must be a positive whole number of seconds, up to 999999999. When specified, Devsy writes `remote.SSH.connectTimeout` to the host user settings for the selected editor flavor. This setting applies globally to all Remote - SSH hosts in that editor, including non-Devsy hosts. If the option is not set, Devsy leaves the existing timeout unchanged. For other VS Code-based editors, use their IDE name in place of `vscode`.

### JetBrains IDEs

Install [JetBrains Gateway](https://www.jetbrains.com/remote-development/gateway/). You need a license for the IDE you use. Start the workspace with the IDE name, for example:

```sh
devsy workspace up my-workspace --ide goland
```

Devsy installs the IDE server in the workspace and opens Gateway. Click **Check Connection and Continue** in the prefilled SSH dialog. If that fails, connect Gateway to `WORKSPACE_NAME.devsy` over SSH.

Fleet works only through a manually added SSH connection to `WORKSPACE_NAME.devsy`.

### SSH

When SSH configuration is enabled, Devsy adds a `WORKSPACE_NAME.devsy` entry to `~/.ssh/config` on the machine running Devsy when it creates a workspace.

```sh
ssh WORKSPACE_NAME.devsy
```

Any IDE with remote SSH support can use this host. Without an `ssh` client, use the CLI:

```sh
devsy workspace ssh my-workspace
devsy workspace ssh my-workspace --command "echo Hello World"
```

If you are already inside a Devsy container and need the host and remote user for a manually configured IDE connection, run this from the container terminal:

```sh
devsy container info
devsy container info --result-format json
```

Run `devsy container info` inside the workspace container, not on your local machine. The printed `ssh` command works only from a client that has the matching Devsy SSH configuration on its host and a reachable transport. The `.devsy` suffix is an SSH alias that Devsy writes to the SSH config, not a network name that resolves on its own.

When Devsy runs on a remote VM, a separate laptop or IDE client needs its own working SSH transport or host configuration. `devsy container info` does not configure it.

Docker Compose workspaces created before Devsy injected `DEVSY_WORKSPACE_ID` into the service lack that variable, so `devsy container info` fails in them. Recreate the workspace to fix it.

## IDE options

Each IDE has options such as the version. List and change them with:

```sh
devsy ide get openvscode
devsy ide set openvscode -o VERSION=v1.76.2
```

You can also set an option for a single workspace with `--ide-option VERSION=...` on `devsy workspace up`.

## Desktop shortcuts

- `Cmd/Ctrl + K` opens the command palette.
- `Cmd/Ctrl + N` starts the New Workspace wizard.
- `Cmd/Ctrl + 1` to `8` jumps between the main sections.
- `Esc` closes the open sheet, dialog, or palette.
