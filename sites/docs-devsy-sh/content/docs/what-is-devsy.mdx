Devsy creates development workspaces from a [devcontainer.json](https://containers.dev/) in your repository. A workspace runs as a container, a Kubernetes pod, or a microVM. Your IDE connects to it.

  <figcaption>Devsy</figcaption>
</figure>

A [provider](./managing-providers/what-are-providers) decides where a workspace runs: your machine, an SSH host, Kubernetes, or a cloud. You can also [write your own](./developing-providers/quickstart). Devsy creates and manages every workspace the same way, whatever the provider.

## Benefits

- **One environment definition.** `devcontainer.json` is an open standard. The same file works on every provider.
- **Your infrastructure.** Run workspaces on machines you already have. Machine providers can stop idle machines with an [inactivity timeout](./developing-in-workspaces/inactivity-timeout).
- **Portable workspaces.** Recreate a workspace on another provider with the same definition. To also move container and volume state, [snapshot](./developing-in-workspaces/workspace-snapshots) a local-provider workspace that has a single bind mount.
- **Your editor.** VS Code, the JetBrains IDEs, and any editor that can connect over SSH.
- **Desktop app and CLI.** Use the desktop app day to day. Use the CLI for automation.
