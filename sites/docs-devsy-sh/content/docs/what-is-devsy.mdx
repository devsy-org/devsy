Devsy creates development workspaces from a [devcontainer.json](https://containers.dev/) in your repository. A workspace runs as a container, a Kubernetes pod, or a microVM. Your IDE connects to it.

  <figcaption>Devsy</figcaption>
</figure>

A [provider](./managing-providers/what-are-providers) decides where a workspace runs: your machine, an SSH host, Kubernetes, or a cloud. You can also [write your own](./developing-providers/quickstart). The provider handles access to that environment; you use Devsy to create, connect to, and stop the workspace.

## What you can do

- Define your project's tools and setup commands in `devcontainer.json`, an open standard. Runtime-specific settings, such as host mounts, may need changes when you switch providers.
- Run workspaces on machines you already have. Machine providers can stop idle machines with an [inactivity timeout](./developing-in-workspaces/inactivity-timeout).
- Recreate a workspace on another provider with the same definition. A [snapshot](./developing-in-workspaces/workspace-snapshots) can also move the container filesystem and a host bind-mounted workspace. Move named volume data separately.
- Connect with VS Code, a JetBrains IDE, or any editor that supports SSH.
- Use the desktop app for daily work and the CLI for automation.

## Start a workspace

[Install Devsy](./getting-started/install), then follow the [quickstart](./getting-started/quickstart) to start a workspace with Docker. If you already have a workspace, see [Connect to a workspace](./developing-in-workspaces/connect-to-a-workspace).
